# Optional Codex connection

Clankwerk provides an **opt-in** connection for single-operator, self-hosted projects using OpenAI's [Sign in with ChatGPT flow for open-source clients](https://developers.openai.com/siwc/token-sharing-open-source/sign-in/). The normal scaffold has no OAuth login, Codex model, or credential store. The connection does **not** obtain an OpenAI Platform API key and does **not** route ChatGPT-plan tokens through Cloudflare AI Gateway. Requests go directly to `https://api.openai.com/v1/responses` with `store: false` and `stream: true`.

## Ownership

The shared React/Vite dashboard, optional Settings card, login helper, encrypted `CodexConnection` Durable Object, Settings request handler, and direct Responses API model adapter live in `@leostera/clankwerk`. An instance still owns its Access policy, Worker binding/secret, feature flag, agent model choice, its own code workspace and its authorizations for any tool execution. `r4` is an example instance; it must not serve as the canonical UI.

## Opt in for a private instance

1. Install React 19, React DOM, and lucide-react if consuming the shared dashboard; the generated template already does. Import `@leostera/clankwerk/dashboard` from the Vite client entrypoint. Serve built assets and `/settings` **only on an Access-protected admin host**; never on the public trigger hostname.
2. Export `CodexConnection` from `@leostera/clankwerk/connectors/codex` in the instance Worker. Add a SQLite Durable Object export and a `CODEX_CONNECTION` binding pointing to that class. Give it one stable instance name for this operator. Add `CODEX_ENCRYPTION_KEY` as a Worker secret (base64 of 32 random bytes); keep a private backup, as changing it makes saved connections unreadable. Do not expose the binding to the code Sandbox.
3. After the admin host gate, route `/api/settings/codex` to `handleCodexSettingsRequest(request, env.CODEX_CONNECTION.getByName("operator"))` from `@leostera/clankwerk/connectors/codex-settings`. The handler enforces same-origin mutations, caps input, and returns no tokens. Route `/api/settings/codex/models` and `/api/agents/:id/model` to `handleCodexModelSettingsRequest` from `@leostera/clankwerk/connectors/codex-model-settings`; **allowlist agent IDs** before the agent route. These handlers validate model choices against the account's live list and require same-origin mutations. The instance's `/api/definitions` response must declare `connections: ["codex"]` and `modelConfigurableAgents: ["your-agent"]` for the respective selectors; without these flags no controls appear.
4. In each configurable Think agent's async `beforeTurn`, call `codexModelForAgent(env.CODEX_CONNECTION.getByName("operator"), "your-agent")` from `@leostera/clankwerk/connectors/codex-model` and return `{ model }` when defined. For an agent that must never fall back, pass `true` as the third argument and provide a fail-closed base `getModel()` (see `r4`'s Coder). Other agents may retain a built-in model when no Codex model is selected; a configured choice never silently falls back after an inference failure. The catalog contains only models OpenAI lists as selectable for the connected account; this is **not** a successful inference test.
5. On the operator's **own computer**, run `clankwerk-codex-connect https://<admin-host>` (or the project script). Open that Access-authenticated site's Settings in the same browser and select **Connect ChatGPT**. OpenAI redirects back to the helper's `127.0.0.1:1455` callback; it verifies PKCE state, OIDC nonce, ID-token signature, and granted `chatgpt.tokens.use.direct` scope. It passes the new connection to the admin page, which imports it over the Access session. Do not copy Pi's existing OAuth credentials.

The helper uses OpenAI's dynamic self-hosted registration, not Pi's client ID. It is for a personally operated installation, not a service offering accounts to other users. Tokens remain in the helper's memory during handoff; the private DO stores encrypted credentials and replaces rotating refresh tokens on renewal. The model adapter obtains the bearer token in the Worker and does not give it to the browser or the code workspace. Disconnect removes the stored connection; revoke access in ChatGPT Settings as well. Never log or commit access tokens, refresh tokens, or the encryption key.

The browser handoff and a real turn on the selected model require the operator to authorize the connection; build/test success and a model's presence in the catalog are **not** proof of successful inference. Luna was not listed for the first connected account tested. For remote self-hosted deployments OpenAI also documents [local authorization and protected VM transfer](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms/). This implementation uses a local helper and direct browser handoff rather than copying a pre-existing Pi credential file.
